# 模块 01：数据导入与清洗验收记录

日期：2026-10-21。分支：codex/retail-analysis-system。

## 范围

本轮仅实现数据模块及其演示页面，不实现后续分析和模型。支持单文件 XLSX/UTF-8 CSV、字段校验、分类清洗、原始副本、Parquet、JSON、SQLite 登记、数据版本复用、质量报告和隔离记录导出。Python 读取 API 可选择多个同结构工作表；页面/CLI 多文件批量导入尚未开放。

## 全量数据核对

输入：用户提供的 Online Retail.xlsx，541,909 条明细。默认按原始八字段去重，特殊业务编码隔离。

| 数据去向 | 行数 |
|---|---:|
| 原始明细 | 541,909 |
| 完全重复行移除 | 5,268 |
| 有效商品销售 | 522,574 |
| 取消/退货候选 | 8,728 |
| 隔离记录 | 5,339 |

核对：5,268 + 522,574 + 8,728 + 5,339 = 541,909。

有效商品销售金额为 £10,259,030.24；取消/退货候选带符号金额为 -£479,003.86。金额基于本模块明确的去重、编码隔离和逐行舍入规则，不是原始文件不加区分求和。

去重后客户编号缺失 135,037 行，与原始缺失 135,080 行的计数口径不同。特殊编码 2,841 行；非正价格 2,512 行，问题计数可能重叠，因此不能用二者之和直接推导隔离总行数。

## 验证方式

- 活动自动化测试覆盖字段缺失与重复表头、CSV 错列/引号内换行、XLSX 损坏与多表结构、匿名销售、取消冲突、非有限数值、数值与带时区日期、金额舍入及大数汇总、空表、去重开关、输入不变。
- 持久化测试覆盖同版本复用、策略改变生成新版本、路径穿越拒绝、失败导入不覆盖当前数据、Windows SQLite 句柄关闭和短暂目录锁重试。
- Streamlit AppTest 验证未导入状态的说明，以及已导入状态的指标、分区核对与三类明细预览。
- 已使用真实全量文件运行 CLI，不仅使用测试小样本。
- 在 Windows / Python 3.13 独立虚拟环境验证，依赖版本保存在 requirements-lock.txt。

当前基线：30 项自动化测试通过，Ruff 检查通过。审查发现的问题均补充回归后修复；页面测试须允许本地回环通信。

## 限制与下一模块

- 特殊编码隔离是明确的项目规则，需要时可在 Python 清洗 API 调整，不能把所有记录解释为错误交易。
- 本轮不匹配取消记录与原始订单，不声称确认真实退款原因。
- CSV 仅接受 UTF-8 系列编码，日期仅接受无时区有效时间；不猜测未知数值日期单位。
- 当前导入为本地可信单人用途，未建设多用户权限和任务队列。
- 全量已导入数据可直接供下一个“交易统计与可视化”模块使用。
