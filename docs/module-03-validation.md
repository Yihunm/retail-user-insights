# 模块 03：RFM 用户价值分析

日期：2026-10-26。分支：codex/retail-analysis-system。

## 功能与口径

侧栏新增“RFM用户价值分析”。页面支持参考日、全部历史/90天/180天窗口、五类客户筛选、编号部分匹配、三幅中文图表、中文明细、实际分位点、规则和运营建议。

参考日 T 为零点，默认取最后有效销售日的次日，包括匿名销售的最后日期。观察窗口是 [T−窗口天数,T)，全部历史模式使用所有 T 之前的数据。仅纳入窗口内至少有一次有效购买、有客户编号的人，窗口外历史客户不在本轮评分总体中。

- R：参考日与最近购买日期的自然日差，前一天23:59购买也计1天。
- F：每名客户不同 InvoiceNo 数，同一订单多商品仅计一单。
- M：有效销售的整数分汇总，再显示为英镑；不含取消/退货候选、隔离及匿名交易。
- 20%、40%、60%、80% 分位点使用精确线性插值；超过几个边界，基础分就是1加几，R反向。相同值同分，重复边界可以跳过分值，但评分尺度始终为1–5。
- 分位与M评分基于整数分和 Fraction 精确比较，避免极大金额不同分钱转成浮点后被当作相同值。购买数量使用 Python 标量求和，保留小数且避免 Int64 汇总溢出。

## 分层规则

以下 R/F/M 均表示分数，按顺序匹配：

| 类型 | 条件 |
|---|---|
| 高价值客户 | R≥4 且 F≥4 且 M≥4 |
| 流失风险客户 | 未命中前项，R≤2 且 F≥3 |
| 沉睡客户 | 未命中前项，R≤2 |
| 潜力客户 | 未命中前项，R≥4 |
| 一般客户 | 其余客户 |

每位客户只属于一类。这是项目中的相对评分和业务规则，不是已有标准答案的分类任务，“流失风险”也不表示未来概率。参考日和观察窗口变化会重新评分；类型/编号筛选则保持原总体分位点不变。
