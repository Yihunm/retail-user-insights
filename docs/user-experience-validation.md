# 面向使用者的界面重组

日期：2026-11-06。沿用Streamlit和原有分析算法，将日常操作围绕“看经营情况、找重点客户、查看特征、导出名单”组织。

## 信息架构

| 页面 | 首要任务 | 进阶信息 |
| --- | --- | --- |
| 工作台 | 查看全部历史经营摘要和客户分析入口 | 说明数据期间、匿名统计和规则范围 |
| 经营分析 | 按日期、国家查看销售表现 | 统计口径和版本折叠 |
| 客户价值 | 定位高价值、流失风险等规则客户，导出名单 | 日期和窗口折叠，RFM规则单独标签 |
| 客户分群 | 查看已保存群体画像，筛选客户名单 | 设置折叠，分离效果、PCA和方法在后续标签 |
| 复购与流失 | 查看复购机会或未购买风险名单 | 日期折叠，历史效果与模型说明折叠 |
| 数据管理 | 导入与检查交易文件 | 质量报告、原始明细与清洗口径 |
| 模型实验 | 首次训练、更新模型、算法对比和效果核对 | 原有16种方案与时间划分完整保留 |

页面标题和导航使用业务词汇。深青用于主要操作，海军蓝用于标题和数值，白色工作区配浅灰背景。中文使用系统字体，数字采用Segoe UI；不依赖外部字体服务。保留键盘焦点，窄屏使用纵向布局。

## 交互与状态

- 首页使用真实有效销售汇总，不自动训练、不生成浏览等缺失数据。首尾月份可能不完整，明确提示。
- 首页客户快捷入口将客户类型、全部历史窗口和参考日一起带入客户价值页，确保人数口径一致。
- 首次无数据时只提供明确的导入入口。无预测模型时，引导准备对应任务；不会在打开页面时自动训练。
- 客户分群恢复同一数据版本的最新完整本地报告，保留原有编号、日期、群体和精确金额；跳过不完整、损坏或其他版本的报告。
- 预测业务页读取同任务、同数据版本的最新完整模型，默认展示最新截点名单；任务切换先清空旧结果，客户表格只展示常用业务字段，完整特征仍在导出中。
- 名单筛选和客户搜索不重新训练。预测日期变更只重新推断，任务、模型和截点组成结果标识；换数据版本清理旧预测。
- 导出按钮紧邻名单，标明筛选人数；预测按钮同时标明复购或风险方向。导出说明包含任务、窗口、客户编号搜索、结果筛选、数据版本和阈值。
- 保留未校准分数、规则标签、未来未购买和永久流失之间的区别。经营建议以“可核对、可考虑”表达，不承诺营销效果。
- 旧导航状态自动迁移到对应业务名称，保留原有日期、国家筛选和客户搜索记忆。

## 验证

自动化共208项测试，覆盖原有200项测试，并新增工作台引导、真实金额摘要、快捷入口范围、旧导航迁移、分群报告恢复和损坏回退、跨会话直接看画像、预测业务页自动读取、方向切换、筛选不训练及数据版本失效回归。特别验证从旧3组客户筛选切到有2组报告的新数据版本，会清理旧群体和客户编号筛选。

最终执行结果：`pytest -q -W error` 为208 passed（52.54秒）；Ruff、依赖检查和Git差异空白检查均通过。

真实浏览器验收使用当前Online Retail数据：工作台4,334名已识别客户；高价值入口的ZIP仅含对应类型；恢复分群后搜索客户12347，ZIP只含该客户；分别加载30天复购与60天未购买模型，各显示2,885名客户，核对筛选ZIP的任务、窗口、人数及不含真实标签；访问全部七页，检查浏览过程中未新增训练记录。另以390像素宽度检查工作台布局和水平溢出。

启动、依赖与原有各模块实验结果见README和模块验收记录。所有数据、模型、浏览器临时截图及规划笔记均不提交仓库。
